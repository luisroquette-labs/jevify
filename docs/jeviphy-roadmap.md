# Jeviphy: evidence before sales

Jeviphy builds on Graphify. Speed and relevance claims require a measured comparison against the same Graphify version, graph, hardware, questions, and request budget. Jev is optional.

**Current gate: stage 2 is conditionally validated for cited sources, while the original general-speed gate remains open. Stage 3 failed.** The original [SWEN memory-mode stress test](jeviphy-independent-stress-20261018.md) failed. The [fast-source follow-up](jeviphy-fast-source-stress-20261018.md) passed a predeclared source-cited gate on COESA after a no-source pass-through correction: better precision@5, lower source-backed p50/p95, a positive case-bootstrap p95 interval, and identical no-source controls. The pooled p95 advantage was too small to support a general-speed claim. In the [paid Jev pilot](../.specs/tasks/draft/jeviphy-paid-ranking.feature.md), 19 completed calls left top-five gold hits unchanged at 4/19 and added 649.74 ms p50 / 1,083.09 ms p95 API latency, at US$0.00153493. Jev remains optional and cannot support a performance claim. Stages 4–5 remain paused pending an independent complete-workflow gate for the local source-cited path.

1. **Candidate retrieval (current):** specify and test a bounded source-aware memory candidate pool. Keep the original question mode and unseeded answer fallback intact. Report exploratory retrieval metrics without claiming better answers.
2. **Independent relevance and stress gate:** freeze at least 30 questions from a repository outside the design cohort before inspecting results. Run a matched, repeated offline candidate stress test; review semantic labels independently where feasible. The original all-case p95 gate remains unmet. For the opt-in source-cited path, the separately declared COESA gate passed; continue only with claims explicitly limited to cited-source cases. Source-file overlap alone cannot prove answer quality or a Jev gain.
3. **Paired Jev test (failed):** 19/19 calls completed on identical bounded pools. Ranking did not improve and API latency exceeded the local Graphify query time. Preserve the result; do not tune or repeat it as confirmation.
4. **Graphify comparison:** benchmark the complete Jeviphy workflow and the original Graphify workflow on the same environment and graph. Publish distributions for answer quality, time, and resource use, with the method and limits. Claim an improvement only for metrics that pass this comparison.
5. **Sales page:** design a page in the repository's visual style with a reproducible demo, install path, measured evidence, limits, and a clear call to action. Use “faster” or “more effective” only when stage 4 supports the exact claim; identify Graphify as the foundation and Jev as an optional ranking step.

The upstream Graphify draft PR remains a separate technical feasibility proposal. Outreach to Graphify and Claude Mem should link to evidence and avoid performance claims until stages 2–4 are complete.
